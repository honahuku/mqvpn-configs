# SSH接続可能になった後の作業入口

現段階の成果物はDebian 13向けPlaybookとDocker検証です。実サーバー・G3のIP、SSHユーザー、鍵、NIC識別子は未確定です。実機へはまだ接続・適用していません。

ユーザーが両マシンでSSHを有効にし、このPCから接続可能にしたら、接続先IP／ユーザー／鍵を `inventory/hosts.yml` に設定します。`inventory/hosts.example.yml` が記入例です。Gitクローン直後で実inventoryが無ければ、サンプルをコピーして作成します。固定debが無ければ `scripts/prepare.sh` で取得します。既存の `~/.ssh/config` を使う場合はSSHホスト別名も利用できます。秘密鍵・パスワードはチャットへ貼り付けません。

「後お願い」と適用を依頼されたら、この順に進めます。

1. `scripts/manage.sh connect` でSSH・sudo・OS・NIC・USB識別子を確認する。Pythonが無い場合だけ `bootstrap` を先に実行する。
2. 実測したIP、IF名、USBポート、管理PC送信元、上流管理ネットワークでinventoryを埋める。出演者LANと参加者LANの物理接続を取り違えない。
3. 既存のFW・ネットワーク管理・SSH経路・DHCP予約を確認する。G3の構築中SSH経路を維持する設定にする。
4. `scripts/init-secrets.sh` を一度実行し、固定アーティファクトを確認する。既存の認証情報を消したり再生成しない。
5. サーバー → G3の設定配置 → G3の有効化の順に適用する。G3有効化は再起動を伴う。
6. エラー時はそのタスクの出力、接続先journal、`event-diagnose`、生成設定を読み、原因を修正して同じ入口から再適用する。根拠なく実行済みタスクを飛ばさない。
7. SSHが戻らなければロールバック期限と次の再起動を待ち、元の接続先が戻ったことを確認する。戻る前に別の構築処理を重ねない。
8. 両回線・両LAN・DNS・管理画面遮断・参加者帯域制限・回線断復帰を実機で確認する。機材側の管理画面や無線分離は機種別に設定する。
9. 設定値、実行結果、未検証事項を更新し、このPCに追加導入したツールがあればユーザーへ一覧報告する。

Notionの要件ページは必要に応じて読み直します。ページの内容やチェックボックスは、明示的な編集依頼なしには変更しません。
